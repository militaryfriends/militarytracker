# 대기자 혜택 — 스토어 설정 (2026-11-28)

**결정(대표):** 대기자(사전 신청자)도 결제 수단을 등록해야 무료 기간(3개월 · 1개월)이 시작된다.
무료 기간이 끝나면 월 구독(₩9,900)으로 자동 결제되고, 그 전에 언제든 취소할 수 있다.
같은 원칙으로 웹의 '카드 없는 7일 체험'도 닫았다(`NO_CARD_TRIAL`).

앱 문구(대표 확정 톤): "대기자 명단에 있으시네요! 결제 수단을 등록하시면 3개월이 무료로 지급됩니다. 언제든 취소하실 수 있습니다."

## 흐름

1. 관리자가 Tally 명단을 앱 관리자 화면(MY › 설정 › 관리자 › 대기자 명단)에 넣는다. 기준일까지 신청 = 3개월, 이후 = 1개월.
2. 대기자가 신청 때와 같은 이메일로 가입하고 인증하면, 앱이 알림 · 홈 한 줄 · 구독 화면으로 알려 준다(`sub.waitlist = 'eligible'`).
   이메일이 다르면 웹 구독 화면에 휴대폰 번호를 넣는다.
3. '3개월 무료 받기'를 누르면
   - **iOS:** 서버가 App Store 일회용 오퍼 코드 하나를 그 계정에 묶어 주고, 앱이 App Store 코드 사용 화면을 코드가 채워진 채로 연다 → 애플이 결제 수단을 확인한다 → 무료 기간 시작.
   - **Android:** 대기자 전용 혜택(개발자 결정)으로 Google Play 결제창이 뜬다 → 결제 수단 등록 → 무료 기간 시작.
4. 앱으로 돌아오면 서버가 RevenueCat 에 확인해 프리미엄(무료 체험 중)으로 바꾸고, 대기자 혜택을 '사용함'(`claimed`)으로 적는다.

## App Store Connect (iOS)

메뉴 이름은 콘솔 언어에 따라 조금 다를 수 있다.

1. 앱 › 구독(Subscriptions) › 구독 그룹 › `mt_pro_monthly` › 오퍼 코드(Offer Codes) › 만들기.
2. `대기자 3개월 무료` — 대상: 신규 구독자(+ 만료된 구독자) · 유형: 무료(Free) · 기간: 3개월 · 판매 국가: 대한민국(필요하면 전체).
3. **일회용 코드(One-Time Use Codes)** 를 만든다 — 수량은 3개월 대상 대기자 수보다 넉넉히, 만료일은 출시 후 충분히 길게.
4. 코드 목록(CSV)을 내려받아 앱 관리자 화면 'iOS 혜택 코드' › **3개월 무료** › 만료일(콘솔에서 정한 날) › 붙여 넣기 › 코드 등록.
5. 같은 방법으로 `대기자 1개월 무료`(기간 1개월) → **1개월 무료** 로 등록.

- '남은 코드 보기'로 재고를 본다. 바닥나면 대기자는 "대기자 혜택을 준비하고 있습니다" 안내를 보고, 서버 로그에 `offer code pool empty` 가 남는다 → 더 만들어 넣는다.
- 만료일을 넣어 두면 지난 코드는 나눠 주지 않고, 받아 놓고 안 쓴 사이 만료된 코드는 다시 누를 때 새 코드로 바뀐다.
- 공유용 코드(Custom Code)는 쓰지 않는다 — 퍼지면 명단에 없는 사람도 받는다.
- 코드를 쓰고 앱이 꺼져도, 다음에 앱을 켜거나 다시 열 때 스토어 구독을 확인해 적는다.

## Google Play Console (Android)

1. 수익 창출 › 제품 › 구독 › `mt_pro_monthly` › 기본 요금제 › 혜택 추가.
2. 혜택 ID `waitlist-3m` — 자격 기준: **개발자 결정(Developer determined)** · 단계: 무료 체험 3개월 · 태그: `waitlist-3m`, `rc-ignore-offer` → 활성화.
3. 같은 방법으로 `waitlist-1m` — 무료 체험 1개월 · 태그 `waitlist-1m`, `rc-ignore-offer`.

- 태그 글자는 앱 코드(`src/utils/waitlistOffer.ts` 의 `OFFER_TAG`)와 똑같아야 한다.
- `rc-ignore-offer`: RevenueCat 이 이 혜택을 일반 구매의 기본 옵션으로 고르지 않게 한다(안 달면 일반 구독도 3개월 무료가 될 수 있다).
  빠뜨려도 앱이 한 번 더 거르지만(`storeIap.native.ts` 의 `normalOption`) 꼭 단다.
- 알고 두는 한계: '개발자 결정' 혜택은 누구에게 보일지를 앱이 정한다. 앱을 뜯어 고친 사람은 명단에 없어도 이 혜택을 살 수 있다
  (그래도 결제 수단을 등록하고, 무료 기간 뒤 자동 결제된다). 막으려면 RevenueCat 웹훅으로 산 혜택을 서버에서 확인해야 한다 — 지금은 하지 않음.

## RevenueCat

따로 할 일 없음 — 같은 상품(`mt_pro_monthly`)과 entitlement `pro` 를 쓴다.

## 배포 (대표 OK 뒤에만)

순서: **앱 코드푸시(OTA) · 웹(Hosting) 먼저, 같은 날 바로 Cloud Functions.** 출시(2027-01-01) 전에 둘 다 나가 있으면 사이 틈은 문제가 안 된다.

1. 앱 코드푸시 + 웹 — 새 알림 · 홈 한 줄 · 구독 화면 · 이용약관 · 개인정보처리방침 문구.
2. Cloud Functions — 대기자 → 무료 자격, 오퍼 코드 창고, 카드 없는 체험 닫기.

- 함수가 먼저 나가면 옛 앱은 무료 자격('eligible')을 몰라 일반 구독 화면을 보여 준다 — 거기서 사면 대기자 3개월이 그냥 소진된다.
- 명단은 출시 전에 넣는다. 앱은 계정마다 이메일로 명단을 한 번만 확인한다(그 뒤에 넣은 명단은 휴대폰 번호로만 받을 수 있다).
- 11/28 전에 명단을 이미 넣었다면 한 번 더 넣는다 — 같은 신청 줄의 이메일 · 번호가 한 묶음이 되어, 한 사람이 두 계정으로 두 번 받지 못한다.
- 11/28 전 방식으로 이미 프리미엄을 받은 계정(`claimed`)은 그대로 둔다.

## 테스트 (콘솔 설정 뒤)

TestFlight(iOS) · 내부 테스트 트랙(Android)에서, 대기자 명단에 테스트 계정 이메일을 넣고:

- 알림 "대기자 명단에 있으시네요!" → '3개월 무료 받기' → 결제창에 '3개월 무료 후 ₩9,900/월'이 보이는가
- 돌아오면 구독 화면에 '무료 체험 90일 남음'이 뜨는가, 홈의 한 줄이 사라지는가
- 기기 구독 관리에서 취소가 되는가, 같은 계정으로 다시 누르면(iOS) 같은 코드가 나오는가
- 대기자가 아닌 계정의 일반 구매가 3개월 무료로 잡히지 않는가(Android `rc-ignore-offer`)
